# 非 Codex：优先使用平台自带图片能力

本流程只适用于非 Codex 环境。宿主自身的图片工具是默认入口，不替换为外部生图服务，也不默认运行仓库中的 Python 脚本。

## 制作

1. 确认宿主有可接收原照片的生图或图片编辑能力；不要编造工具名或假设具备裁片、遮罩接口。原图不可访问时先解决输入问题。
2. 阅读本次原照片，按顺序自动选择记忆点。用户指定的内容和取景优先；不额外增加逐张确认步骤，除非用户要求先看候选。
3. 在调用前为整批照片规划连续拼接及互补边界，沿用 SKILL.md 的两套样式、画幅、等分、单元尺寸及整体尺寸上限。每张只提取一个碎片，要求上方、原位缺口与最终拼接使用同一照片局部、相同尺寸和方向。
4. 通过宿主自带能力编辑用户的原照片。明确要求照片保真、暖象牙纸、锐利轮廓、大面积留白；不新增文字、水印、装饰，不更换主体或补画内容。能力支持真实图层或遮罩复用时优先使用，不能把三次独立生成称为复用。
5. 最终拼接使用已完成的碎片作为约束，要求不重新取景、缩放或旋转。若工具无法保持边界和内容，说明未满足严格拼接要求，不把近似拼贴报告为精确成品。
6. 每张保存为独立文件，保留原图及历史输出。默认两套各 N+1 张，不用一张联系表代替单张交付。默认不截图、不启动服务器。

## 交付与精度

- 目标仍为 1800×2400、上下各 1200 像素。工具无法控制目标尺寸时如实报告实际尺寸，不声称满足。
- 只报告实际做过的检查。视觉相似不等于像素一致；没有共用裁片与遮罩的证据、原图坐标核对和边缘检查，不能报告“逐像素通过”。
- 程序路径的 `制作检查.json`、`status: complete` 及其通过记录不得用于生图结果，不得伪造检查报告。
- 严格精确对应无法保证时，输出标为“视觉候选，像素对应未验证”。用户要求精确制作时先说明限制，再依当前授权及宿主规则决定是否采用程序路径。
- 工具不可用或失败时停止该路径，说明原因；没有可用工具时不能以文字描述冒充已生成图片。
