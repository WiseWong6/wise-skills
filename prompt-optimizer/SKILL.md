# Prompt Optimizer

## 可配置项

首次使用时向用户确认以下配置，后续沿用：

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `PROMPT_AUTHOR` | `<待确认>` | 版本头部的 Author 字段 |
| `PROMPT_SAVE_ROOT` | `~/Documents/prompts` | 提示词文件保存根目录 |

## 质量内核

提示词是代码；优化提示词就是做受控变更。默认只修复用户请求对应的问题，不重写无关段落，不添加不必要实体。

先判断目标模型是否开启深度思考：

- 未开启：把提示词收敛成执行型，减少判断、比较、择优和开放分支。
- 已开启：可以保留判断型结构，但必须写清判断标准、优先级和输出结果，不要求输出完整思考过程。

## 进入条件

开始修改前先确定：

- 权威版本：优先读取 `${PROMPT_SAVE_ROOT}/<task-slug>/` 下最高版本号文件；若用户提供了不同文本且差异超出请求范围，先问哪个为准。
- 改动范围：用户指定范围优先；未指定时提出最小相关范围。范围外逐字保留。
- 修订类型：任务目标、受众、输出结构或核心流程大幅变化时，切换到 `prompt-creator` 的重写逻辑。

## 诊断清单

把每个问题映射到具体段落和具体改法：

- MECE：是否有重叠规则、遗漏边界或混合职责。
- 冲突：目标、约束、格式、优先级是否互相打架。
- 冗余：是否多次表达同一规则，导致维护成本上升。
- 歧义：术语、输入、输出、成功标准是否能被稳定执行。
- 范围膨胀：是否为小改动添加模块、角色、阶段或特殊分支。
- 示例质量：示例是否能抽象出方法；不能只靠补更多例子兜底。
- 注释污染：是否有括号式补丁说明或营销式强调词。
- 安全面：是否增加提示注入、权限滥用、数据泄露或不安全委派风险。

## 工作流

1. 读取权威版本；若没有历史文件，将用户提供的提示词视为 `v1.0`。
2. 确定允许改动范围。删除、移动或跨范围修改前必须列出影响并请求确认。
3. 诊断问题，输出“问题是什么、证据在哪、改哪一段、为什么不需要改更多”。
4. 只展示变更段落的 before/after diff；范围外不改写、不重排。
5. 用户确认后输出完整修订稿，版本号 minor +1，更新 `Update`，并保存为新文件，不覆盖旧版本。

## 变更规则

- 添加规则放在最近相关段落，不新开特殊模块，除非现有结构无法承载。
- 删除规则必须说明删除原因；如果风险仍存在，在诊断里标记为超范围残留问题。
- 注释只用 `//` 风格；默认最终保存干净版，不把解释性注释混入提示词主体。
- 不使用括号式补丁标记，不写维护噪声。
- 不通过堆叠标签、特殊模块或示例来掩盖接口不清。

## 版本与头部

版本格式为 `v<major>.<minor>`，默认 minor +1。文件名为 `prompt_v<version>.md`。

```markdown
// {
// Author: <PROMPT_AUTHOR>
// Model: <用户提供的模型列表>
// Update: <本版本实际改动摘要>
// Version: v1.0
// }
```

若缺少 Model，最终保存前向用户索取；若只是给修改提案，可以先保留占位。每次保存新版本都必须更新 `Update`，用一句话描述本次真实改动。

## 可选 Git 管理

保存提示词文件后，可以提示用户是否需要 Git 记录；Git 不是默认流程，也不是强制项。

- 只有用户明确要求 Git 记录时，才执行 Git 命令。
- 先运行 `git status` 确认改动范围。
- 若用户确认提交，使用 `git add <具体文件>`；不要默认使用 `git add .`。
- Commit message 建议：`prompt(<task-slug>): v<version> - <update summary>`。
- Push 不是默认步骤；只有用户明确要求 push 时才执行，并先说明目标 remote 和 branch。

## 可选回滚

默认通过版本文件回滚：从目标历史版本复制内容生成一个新版本，不覆盖旧文件。

若用户要求 Git 回滚，先用 `git status` 和 `git log` 或 `git show` 确认目标版本，再提出恢复方案。不要默认使用破坏性命令；`git reset --hard`、`git checkout -- <file>` 和强制 push 只有在用户明确要求并确认影响后才允许。

## 输出格式

- 提案阶段：诊断摘要、变更范围、before/after diff、残留风险。
- 完成阶段：单一代码块输出完整修订稿，并确认保存路径。
