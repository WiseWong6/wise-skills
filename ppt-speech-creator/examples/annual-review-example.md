## 第 3 页：年度成绩单（待确认）

**表达任务：**
- 让听众在 20 秒内记住“今年整体表现超预期，而且是多维度一起提升”。

**页面构成摘要：**
- 页面骨架：标题区 + 双卡片区 + 趋势区 + 结论区
- 页面节奏：先看结论，再扫数字，再看趋势
- 是否有组件：有，3 个组件

**区域说明：**
- `Header`：标题 + 一句年度结论
- `Hero-Left`：指标卡 1，放目标完成率和用户增长
- `Hero-Right`：指标卡 2，放项目交付和协作数据
- `Support`：一条全年增长趋势图
- `Footer`：一句总括，连接下一页

**ASCII 基础格式：**

```text
+------------------------------------------------------------+
| 2024 年度成绩单                                             |
| 超额完成目标，增长、交付、协作三线同时向上                 |
|------------------------------------------------------------|
| +----------------------+  +------------------------------+ |
| | 指标卡 1             |  | 指标卡 2                     | |
| | 完成率 108%          |  | 项目交付 8 个                | |
| | 用户增长 +45%        |  | 跨部门协作 12 个项目         | |
| +----------------------+  +------------------------------+ |
|------------------------------------------------------------|
|                    全年趋势图 / Q1-Q4 跃升                  |
|------------------------------------------------------------|
| 结论：这不是单点突破，而是系统性表现提升                   |
+------------------------------------------------------------+
```

**组件清单：**
- `.stat-card` x2：承载四个核心数据
- `chart` x1：趋势图

**文案要点：**
- 标题：2024 年度成绩单
- 结论句：超额完成目标，增长、交付、协作三线同时向上
- 支撑点：
  - 目标完成率 108%
  - 用户增长 +45%
  - 8 个项目按时交付
  - 跨部门协作覆盖 5 个部门、12 个项目

**配图建议：**
- `chart`

**逐字稿（约 90 秒）：**

> 先用一页快速看今年的整体成绩。最关键的一点是，今年不是某一个指标偶然表现好，而是增长、交付和协作三个维度一起向上。
>
> 左侧两项是最直接的业务结果。目标完成率达到 108%，说明年初承诺的目标不仅完成了，而且有超额。用户增长达到 45%，明显高于最初 30% 的目标。
>
> 右侧两项说明，这个结果不是靠透支团队换来的。今年我负责和参与的 8 个项目全部按时交付，同时推动了 12 个跨部门项目协同落地。
>
> 下方的趋势图能看到两个明显跃升节点，这也为后面几页展开核心成果做铺垫。

## 第 4 页：用户增长突破（待确认）

**表达任务：**
- 让听众理解“增长不是一句话结果，而是由留存、获客成本和 DAU 共同构成的突破”。

**页面构成摘要：**
- 页面骨架：标题区 + 左右双组件区 + 底部文案区
- 页面节奏：左看结果，右看原因，底部收束判断
- 是否有组件：有，2 个组件

**区域说明：**
- `Header`：标题
- `Main-Left`：指标卡组，展示 DAU、CAC、留存率
- `Main-Right`：趋势图，展示 Q2 和 Q4 两次跃升
- `Footer`：一句结论 + 两条原因说明

**ASCII 基础格式：**

```text
+------------------------------------------------------------+
| 用户增长突破                                                 |
|------------------------------------------------------------|
| +----------------------+  +------------------------------+ |
| | 核心指标卡组         |  | DAU 年度趋势图               | |
| | DAU: 50w -> 72w      |  | Q2 跃升：推荐算法上线        | |
| | CAC: -32%            |  | Q4 跃升：邀请有礼活动        | |
| | 7 日留存: 35% -> 48% |  |                              | |
| +----------------------+  +------------------------------+ |
|------------------------------------------------------------|
| 结论：增长来自产品优化和运营策略协同，而不是单点投放放量   |
+------------------------------------------------------------+
```

**组件清单：**
- `.stat-card`
- `chart`

**文案要点：**
- 标题：用户增长突破
- 结论句：增长来自产品优化和运营策略协同
- 支撑点：
  - DAU 从 50 万增长到 72 万
  - 获客成本下降 32%
  - 7 日留存率从 35% 提升到 48%

**配图建议：**
- `无`

**逐字稿（约 120 秒）：**

> 这一页我想说明，用户增长不是一个单独数字，而是一组相互联动的数据结果。
>
> 左侧先看三个核心指标。第一，DAU 从 50 万增长到 72 万。第二，获客成本下降了 32%，说明增长效率更高。第三，7 日留存从 35% 提升到 48%，这意味着增长质量也在提升。
>
> 右侧趋势图可以帮助大家理解这不是线性自然增长。Q2 的跃升来自推荐算法上线，Q4 的跃升来自邀请有礼活动。也就是说，增长是产品能力和运营动作共同作用的结果。
>
> 所以这页真正想传达的不是“我们涨了 45%”，而是我们已经初步建立了一套可复制的增长机制。

## 第 6 页：重点项目复盘（待确认）

**表达任务：**
- 让听众理解“这个项目为何重要、我做了什么、为什么结果可信”。

**页面构成摘要：**
- 页面骨架：标题区 + 上方文案区 + 下方双组件区
- 页面节奏：先交代背景与结论，再展示过程和验证方式

**区域说明：**
- `Header`：标题 + 项目一句话定义
- `Body`：背景、角色、最终结果
- `Support-Top`：流程图，展示调研到上线的关键动作
- `Support-Bottom`：A/B 测试结果区，展示验证逻辑

**ASCII 基础格式：**

```text
+------------------------------------------------------------+
| 「新用户激活」项目复盘                                      |
| 留存问题不是表层现象，关键在首日体验和兴趣匹配             |
|------------------------------------------------------------|
| 背景：7 日留存率低于行业平均 10 个百分点                   |
| 角色：项目负责人                                            |
| 结果：正式上线后留存提升 13 个百分点                        |
|------------------------------------------------------------|
| 调研 -> 方案设计 -> 5 轮 A/B 测试 -> 正式上线              |
|------------------------------------------------------------|
| 测试结果区：痛点 3 个 / 最终保留方案 1 个 / 提升 +13pct     |
+------------------------------------------------------------+
```

**组件清单：**
- `.process-chain`
- `.stat-card`

**文案要点：**
- 标题：「新用户激活」项目复盘
- 结论句：关键在首日体验和兴趣匹配
- 支撑点：
  - 访谈 50+ 新用户
  - 识别 3 个核心痛点
  - 完成 5 轮 A/B 测试
  - 正式上线后提升 13 个百分点

**配图建议：**
- `diagram`

**逐字稿（约 180 秒）：**

> 这一页我重点复盘今年最重要的项目，新用户激活优化。先说结论，这个项目之所以能做出结果，不是因为我们简单改了一个流程，而是找到了影响留存的关键环节，也就是首日体验和兴趣匹配。
>
> 中间这块先交代背景。年初我们发现，新用户 7 日留存率低于行业平均 10 个百分点，这意味着大量用户第一次使用后就流失了。我在这个项目里担任负责人，负责把调研、方案设计、测试和上线串起来。
>
> 下方第一块展示的是过程。我们先访谈了 50 多位新用户，识别出 3 个核心痛点，然后围绕 onboarding 和个性化推荐设计方案，最后做了 5 轮 A/B 测试。
>
> 最下面这块是为什么这个结果可信。不是拍脑袋觉得方案更好，而是经过多轮测试才收敛到一个最优版本。正式上线后，7 日留存率提升了 13 个百分点，比预期还多 3 个点。
