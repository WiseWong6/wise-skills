# 推荐组件库

本文件列的是推荐组件，不是整页结构。

这些组件可以单独使用，也可以组合使用，还可以完全不用。

## 组件分类

### 对比类

- `.vs-grid`
  - 用于旧 vs 新、方案 A vs B、现状 vs 目标
- `.comparison-table`
  - 用于多方案多维度比较
- `.venn`
  - 用于交集、重叠关系

### 流程类

- `.process-chain`
  - 线性步骤，适合 3-6 步
- `.process-loop`
  - 闭环、迭代、循环
- `.timeline`
  - 时间推进、里程碑、路线图
- `.journey`
  - 用户旅程、体验路径
- `.gantt`
  - 排期与并行任务

### 结构类

- `.matrix-grid`
  - 象限、矩阵、多维分类
- `.concentric`
  - 核心到外延
- `.pyramid`
  - 层级、战略分解、漏斗
- `.mind-map`
  - 发散结构、概览
- `.architecture`
  - 系统、平台、模块分层

### 分析类

- `.fishbone`
  - 根因分析
- `.iceberg`
  - 表层与深层
- `.radar`
  - 多维能力评估

### 数据类

- `.stat-card`
  - 核心数字、关键指标

### 文本强调类

- `.quote`
  - 金句、转场、价值判断
- `.alert-box`
  - 风险、边界、提醒
- `.terminal-box`
  - 概念定义、术语、命令
- `.code-block`
  - 技术代码、接口示例
- `.title-card`
  - 封面、章节分隔
- `.list-card`
  - 简单清单、短要点

## 组合建议

常见高质量组合：

- `.stat-card` + `.timeline`
  - 先给结果，再给过程
- `.vs-grid` + 行动文案
  - 先比较，再给判断
- `.fishbone` + 总结文案
  - 先分析原因，再给结论
- `.process-chain` + `.stat-card`
  - 解释流程，同时强调关键结果
- `.matrix-grid` + `.alert-box`
  - 分类讨论后指出风险或重点

## 不要这样用

- 不要把 `.three-col`、`.split-v` 视为组件
  - 它们属于页面骨架，应在页面构成层处理
- 不要强迫每页挂一个组件标签
- 不要为了“显得丰富”而在同一页堆 3 个以上独立组件
- 不要让组件和正文重复说同一件事

## 选择原则

- 如果页面主要任务是“让人一眼理解关系”，优先结构类或对比类
- 如果页面主要任务是“证明结果”，优先数据类
- 如果页面主要任务是“讲过程”，优先流程类
- 如果页面主要任务是“做判断或提醒”，优先文本强调类
- 如果页面主要任务是“过渡”，组件可以为空
