# 页面构成参考

本文件只回答一个问题：一页 PPT 应该如何组织空间与信息。

不要把页面构成等同于“选一个组件”。页面构成是：

`页面骨架 + 区域职责 + 组件/文案分布`

## 页面骨架

常用骨架：

1. 居中骨架
   - 标题在上
   - 组件或核心结论居中
   - 说明文案在下
2. 左右骨架
   - 适合主次对照、图文配合、证据与说明并置
3. 上下骨架
   - 适合“先结论后展开”或“上文下图”
4. 三栏骨架
   - 适合并列三项，不适合塞过多小字
5. 网格骨架
   - 适合矩阵、卡片、分类对照
6. 主次区骨架
   - 一块主区域承载重点，一块辅区域给解释、注释或补充信息
7. 纯文字骨架
   - 适合过渡、结论、价值观、金句

## 区域职责

典型区域：

- `Header`
  - 标题、副标题、页内结论
- `Hero`
  - 本页最重要的可视化组件或一句大结论
- `Body`
  - 说明文案、支撑点、细节
- `Support`
  - 辅助证据、次要组件、图例、备注
- `Footer`
  - 一句话总结、行动建议、来源、注释

不是每页都要有全部区域。关键是区域职责清楚。

## 组合模式

### 1. 标题 + 多组件 + 文案

适合：
- 年度成绩单
- 产品优势页
- 数据证据页

典型结构：

```text
+------------------------------------------------------------+
| 标题 + 结论句                                               |
|------------------------------------------------------------|
| 组件 1                  | 组件 2                           |
|------------------------------------------------------------|
| 文案总结 / 补充说明                                        |
+------------------------------------------------------------+
```

### 2. 标题 + 居中组件 + 文案

适合：
- 流程解释
- 机制拆解
- 架构概览

典型结构：

```text
+------------------------------------------------------------+
| 标题                                                       |
|------------------------------------------------------------|
|                                                            |
|                    主组件居中                              |
|                                                            |
|------------------------------------------------------------|
| 解释文案 / 结论                                            |
+------------------------------------------------------------+
```

### 3. 标题 + 文案 + 上下组件

适合：
- 先讲判断再给证据
- 先讲问题再讲原因
- 复盘与改进页

典型结构：

```text
+------------------------------------------------------------+
| 标题                                                       |
|------------------------------------------------------------|
| 上方文案 / 结论区                                          |
|------------------------------------------------------------|
| 组件 A                                                     |
|------------------------------------------------------------|
| 组件 B                                                     |
+------------------------------------------------------------+
```

### 4. 标题 + 左图右文

适合：
- 对比说明
- 产品方案
- 数据图 + 行动建议

### 5. 纯文字页

适合：
- 章节过渡
- 金句
- 最终总结

典型结构：

```text
+------------------------------------------------------------+
|                                                            |
|                       主标题                               |
|                                                            |
|                    一句核心表达                            |
|                                                            |
|                  补充说明或演讲人                          |
|                                                            |
+------------------------------------------------------------+
```

## 决策规则

### 何时减少组件

- 本页核心表达可以一句话说清
- 观众此时需要停顿，而不是继续接受结构化信息
- 上一页已经很复杂，本页需要减负

### 何时增加组件

- 只有文字会导致认知负担过高
- 需要同时呈现结论和证据
- 需要并列多个维度，且口头解释不足以支撑理解

### 何时拆页

如果出现以下情况，优先拆成两页，而不是继续堆布局：
- 标题之外还要放 3 个以上独立组件
- 一个页面同时承担“解释背景”和“展示结果”两个核心任务
- ASCII 骨架已经明显拥挤

## ASCII 要求

- 默认按 16:9 思维绘制
- 宽度约 60-70 个字符
- 高度约 20-25 行
- 优先让用户看懂区域关系
- 不要求把每个组件内部画得很精细
