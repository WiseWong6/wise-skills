# 简历复核清单

按工作方式和交付阶段检查。诊断与写作使用 [主文件](../SKILL.md) 中的同一套简历结构。

## 仅排版

- [ ] 对照原文，文字未擅自润色、补写或删减；识别不清之处已询问。
- [ ] 缺少简介或辅助内容时没有编造填空，内容建议与排版修改分开。
- [ ] 只调整排版，不借排版替用户决定内容取舍。

## 诊断与优化

### 诊断输出

- [ ] 按基础信息、个人简介、工作经历、辅助内容逐项诊断，再做全篇复核。
- [ ] 每个有问题的模块给出具体位置、修改理由、改法和必要示范；模块内优先说明重要问题，不凑问题数量。
- [ ] 确认方向后再改全文；仅诊断时到建议为止。真实性、岗位相关性和可理解性贯穿各模块。
- [ ] 岗位资料优先采用用户原文；搜索资料注明来源并区分实际岗位要求与同类参考，没有资料也可通用诊断与优化，不把推测的求职意向写成事实。
- [ ] 已获现有资料内优化授权时先交完整优化稿，未要求重复确认或补齐材料；从仅排版转入优化后重新审查所有模块。缺口局部处理，未以诊断、改写示范或问题清单代替完整稿，正文无待填占位。

### 基础信息

- [ ] 基础信息仅从姓名、联系方式、用户确认的当前常驻城市、用户提供用于简历的本人头像四类中选用，范围外字段已删除且未挪到其他栏目。
- [ ] 当前常驻城市没有由其他地点推断或替代；缺失信息已询问或省略，没有填空或混入案例资料。

### 个人简介

- [ ] 定位清楚，能看出经验、领域与代表价值；有岗位要求时针对性突出优势。
- [ ] 支撑具体、有辨识度，不只是名企标签、通用职责或能力自评。
- [ ] 第三句优先选取有依据、与岗位相关且有辨识度的具体事情，如开源贡献、独立开发作品或有分量的奖项；其次才是用户自述的价值观、性格或兴趣实践，没有用泛泛标签凑句数，也没有由业绩推断性格。
- [ ] 第三句未重复前两句的同一组依据；简介概括作品或奖项时，后文只补充必要依据，不重复整句，个人与团队归属准确。
- [ ] 建议三句、允许一至三句，已有各句各有作用，不为句数重复或凑内容。

### 工作经历

- [ ] 任职按时间倒序，日期与任职关系准确；公司或产品易识别，职位具体到真实业务方向，不升级职级。
- [ ] 经历标题只包含日期、公司或产品名称、职位，没有附加任职地区或在职位中拼接地点；真实名称中的地域字样未被误删。
- [ ] 项目归入对应任职，贡献正文开头突出有依据的贡献或实践重点，同层要点分工清楚；有成果时对应行动，无成果材料时未强凑结果句。
- [ ] 背景、任职总述、贡献要点、荣誉各有归属且按需保留；总述未与分项并列，奖项和考核未混入总述或充当另一项贡献。
- [ ] 并列贡献采用同一种划分标准，彼此不包含或重叠，覆盖说明所选贡献所需的关键依据；一段任职可有多项独立贡献，没有强拼项目、重复行动或为凑类别保留弱相关内容。
- [ ] 模糊经历从具体事件中性追问，再提炼能力；关键判断有依据和约束，没有把执行写成主导决策，也没有把事后认识写成当时的分析。
- [ ] 涉及用户价值或流程改变时，写清实际使用者、原来做法与关键变化；没有用管理者认可代替一线体验，也没有忽略已知的新增负担。
- [ ] 本人贡献与团队成绩、总量与增量、实际与目标预测分清；前后数字比较的范围、口径和因果依据清楚，没有把收窄范围后的结果写成整体提升。
- [ ] 每个数字的产品、业务、时间和角色归属在合句或移位后仍准确；团队或跨任职区间的增长没有仅靠移入背景判为合格。不必要的数字已省略，口径不清的比例未被提升为开头亮点。
- [ ] “缺少成果”已结合原材料判断，分别追问、选入已有成果或整理已有主线；没有收益数字时分清未统计、价值不在直接增长和最终收益尚未出现，采用对应的真实证据。
- [ ] 阶段成果说明验证发现、障碍解决或决策变化怎样支撑目标，不把完成文档、设置机制或未发生事故直接当成最终收益，不把停止方案折算成无依据的节省金额。
- [ ] 认可、试用与持续采用没有混写；影响成果解释的试点范围、人工辅助或组织要求得到保留，也没有因此否定已发生的使用价值。
- [ ] 所选指标能说明目标，材料中的质量、投诉或人工负担等代价没有被有意省略；项目整体结局与个人贡献分开，没有把局部成果包装成整体成功，也没有强求失败经历必须有后续成功应用。
- [ ] 按岗位相关性、本人贡献和证据强度筛选经历，重要贡献没有被通用职责和功能清单淹没，工作量或规模只在有解释价值时突出。
- [ ] 陌生业务有必要解释，专业术语得到保留，跨行业读者能理解主要贡献。

### 辅助内容

- [ ] 教育、技能、语言、荣誉等真实且有补充价值，不为栏目齐全或填满页面添加内容。
- [ ] 优化时默认不设技能栏；保留的仅为具体、与岗位相关、有依据且补充独立信息的专业技能，没有通用工具清单、泛泛的能力标签或重复经历的条目；无合适内容时整个栏目已删除。仅排版时保留原文，建议另列。
- [ ] 不以技能自评替代经历证明，不把集体荣誉写成个人获奖，也不另列项目重复展开工作成果。

### 全篇复核

- [ ] 不依赖修改说明，新版也能更快看出候选人定位、主要经验和本人贡献；重要经历与支撑信息更突出，诊断发现的重复或理解负担确有改善。没有把换词、合句或增加总述自动当作完成优化，也未为改动数量强改已有清楚内容。
- [ ] 按含义逐句核对事实、角色、范围与结论强度，归纳句可由多处材料支撑，不以原句匹配否定改写；逐项审查全部保留字段的用途、归属和必要性。
- [ ] 诊断提出的问题逐项已修正或明确待确认；删改没有损失影响判断的事实条件，没有把关键词命中或未新增数字当作内容优化通过。
- [ ] 简介的判断有经历或用户补充支撑，各模块中的时间、角色和数字无矛盾。
- [ ] 简介概括、经历展开构成合理分工；没有换栏目或措辞重复同一段内容，也没有强行拼职业故事。
- [ ] 整体重点、篇幅和岗位方向一致；缺岗位资料时没有臆造匹配结论。
- [ ] 全篇排版问题得到说明，实际页面按下节检查；跨模块问题集中处理，不重复各模块已指出的问题。

## HTML 交付

- [ ] 四个内容模块保持设计规范中的位置和阅读顺序；辅助内容不抢占核心位置。
- [ ] 业务背景、任职总述和任职荣誉补充使用贡献列表之外的普通段落，无序号或圆点；多项并列贡献才使用列表，序号从第一项贡献开始，单项未为编号硬拆。
- [ ] 新建默认多页竖版、纯白背景、正黑配色、霞鹜文楷；用户已明确选择的外观得到保留。
- [ ] 多页竖版一般 1–2 页，资深且内容有价值时可到 3 页；单页侧版严格一页。
- [ ] 优化或已授权补充内容时，侧版右栏等大段空白已优先通过保留或补回已有材料中有价值的贡献、判断、行动及结果来减少，没有过度精简、重复凑字或编造，也没有靠拉大间距、行高或字号填满；仅排版未擅自补写。
- [ ] 复用原有字体、颜色、背景、头像、列表和间距规则，不缩字或隐藏溢出。
- [ ] 每段工作经历的日期、公司或产品、职位完整处于同一行，每项及整组均不折行；没有靠缩字、裁切、隐藏、省略号或叠字实现。仅排版与原文冲突时已说明待处理项，未判为通过。
- [ ] 工作经历章节保留 `data-section-type="work"`，标题检查能够覆盖该章节；过长、折行或相互重叠时提示具体标题并禁用打印。侧版教育仍按三行排列，不受工作标题单行限制。
- [ ] 正文强调只复用既有字重和强调色，不层层叠加标记。
- [ ] 本地字体、样式、控件与分页文件路径有效，所选字体与外观设置一致；仅交一版时不保留指向缺失文件的版式选项。
- [ ] 请用户打开网页核对 A4 分页、页数、溢出、工作经历标题是否完整保持一行及其与首条内容的位置；字体、标题或分页问题未解决时不进入正式打印。未实测的项目明确待验收，不能用标签闭合、资源齐全或无横向溢出代替。
- [ ] 对照原文或确认后的文案核对内容完整性；程序检查不能代替此项。
- [ ] 可以通过 `file://` 打开，未启动无必要服务器或擅自截图。
- [ ] 请用户验收内容与视觉，尚未确认时没有生成 PDF。

## 确认后的 PDF

- [ ] 用户已确认当前 HTML 的内容与视觉，PDF 使用同一文案及外观选项。
- [ ] A4 尺寸、页数、工作经历标题单行及与首条内容的位置正确，字体已嵌入，无乱码或裁字。
- [ ] HTML 与 PDF 提取文字去空白后逐字一致，阅读顺序正确。
- [ ] PDF、HTML 文案和检查报告对应同一次交付。

## 结束时说明

按授权方式说明交付：仅诊断给建议，仅排版给原文排版稿；优化任务先给完整优化稿及关键改动，用具体前后差异说明改善了什么，再报告检查结果。补充问题仅保留能明显改善下一版的少量问题，并说明用途；用户已明确不补充时不重复追问。不得因缺数字宣称已达优化上限。源码核对、写作判断和用户视觉验收分别报告；未实际验证的字体、分页或 PDF 项目如实说明。
