# 本技能的提示词与规则维护

用于创作、编辑和诊断 wise-resume 的主提示词、参考方法、复核清单、入口说明及模板。不据此修改其他技能或全局规则。

## 定义先于措辞

先写清适用对象、条件、预期结果和检查方式，再写指令。主文件定义内容含义及取舍，设计规范定义显示方式；参考方法解释难点，示例演示规则，模板承载文案，复核清单检查结果。后几者不能各自引入另一套内容原则。

规则分组也采用“同层不重叠、覆盖当前任务”的原则：同一层按同一种标准划分，说明上层概括与下层支撑的关系。真实性是所有内容都需满足的条件，不能与背景、贡献、荣誉等内容类型当成同级栏目；编号是显示方式，不能决定某句属于总述还是贡献。

## 创作和编辑流程

1. 阅读当前主文件、受影响的参考文件、模板与适用用户指令，确认工作方式和授权范围。已有规则优先修改原位置，避免在末尾不断追加例外。
2. 给容易混淆的概念划清范围：处理什么信息、与相邻概念是什么关系、何时使用或省略。只定义解决当前问题所需的区别，不新增必须填齐的栏目。
3. 写出可以观察到的结果及检查方式。例如“总述放在列表外的普通段落”比“注意层次”更明确；“每个数字能回查到对象和时间”比“数字真实”更具体。
4. 同步主文件、设计规范、相关示例、模板占位、复核清单与入口摘要。明确只改规则或不改真实产物的任务，保留该边界，并说明任何尚未同步的实现。
5. 对照原文审阅改动：新规则是否改变原有授权、引入重复或与相邻规则冲突；示例和模板是否有反向诱导。必要时用少量虚构情境逐项核对，不把真实候选人材料写入公开示例。

## 诊断失败产物

先还原实际证据：用户请求、使用模型、当时加载的技能内容、读取结果、生成文案及相关模板。不能仅根据现在磁盘上的规则推断模型当时读到了什么，也不把换模型或重新加载当成默认解法。

按原因定位，不按文件数量重复报问题：

| 检查对象 | 要回答的问题 |
|---|---|
| 输入与加载 | 原材料和当前请求是否完整，是否读到适用规则？ |
| 规则定义 | 概念、适用条件、优先关系是否清楚，是否存在遗漏或矛盾？ |
| 示例与模板 | 是否把正确规则示范成了错误层级、分组或显示方式？ |
| 实际执行 | 在明确且一致的要求下，模型具体违反了什么？ |
| 结果验证 | 检查是否能发现该错误，报告是否超出实际验证范围？ |

同一问题可以跨多个环节形成因果链，只报告一次并关联证据。规则缺陷与执行偏差可以同时成立；发现规则冲突要先消除冲突，规则清楚但被忽略则明确记录执行失败。一次会话只能证明该次执行表现，不能单凭印象认定模型整体能力。

## 必要复核

- 内容层级：背景、总述、并列贡献、荣誉各有用途；结果归到所证明的贡献，父项不与子项并列。
- 分组标准：并列项采用同一标准，范围不包含或重叠；覆盖已选贡献所需的关键依据，不靠凑类追求形式完整。
- 事实归属：多产品、多项目、多时间段的指标没有被合句或换栏目转移；不确定内容按现有资料成稿规则局部处理。
- 工作方式：只诊断、只排版、已授权优化的行为不混淆；缺少补充资料仍能交已有事实支持的完整稿。
- 显示映射：总述无编号，贡献列表的序号从第一项贡献开始；模板占位不要求虚构结果、重复简介或补齐不存在的栏目。

检查通过后说明改了什么、保留了什么、哪些只做了规则或源码检查。用户留待另一会话测试时，不替用户运行该会话或改动其测试简历；实际模型执行效果仍须由下一次测试验证。
